  一句话定位

  单进程、内存驻留、C++17 的近似最近邻向量数据库：数据以扁平数组驻留内存，提供 CRUD + 暴力/近似双路检索 + 二进制持久化，全部无外部依赖。

  一、三层架构

  ┌─ VectorDb.h    门面层：统一 API、编排各层、持久化入口
  ├─ VectorTable.h 数据模型层：向量怎么存、怎么删、怎么改
  └─ HnswIndex.h   索引层：近似检索图，只引用表，不复制向量

  ┌─────────────┬──────────────────────────────────────────────────────────────────────────────────────────┬───────────────────────────────────────────────────────┐
  │     层      │                                           职责                                           │                      关键不变量                       │
  ├─────────────┼──────────────────────────────────────────────────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
  │ VectorTable │ 扁平连续存储 data_[id*dim, +dim)；软删除位图 deleted_；count()=存活、slot_count()=总槽位 │ 余弦模式写时 L2 归一化，存的就是单位向量              │
  ├─────────────┼──────────────────────────────────────────────────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
  │ HnswIndex   │ 分层可导航小世界图：node_level_(每槽层高)、links_[槽][层][邻居]、enter_point_/top_level_ │ 与表共享维度/度量；死边容忍（指向已删节点的链接无害） │
  ├─────────────┼──────────────────────────────────────────────────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
  │ VectorDb    │ 串起上两层；暴力 Top-K（精确基准）；Save/Load                                            │ 数据一致性靠 table_；索引一致性靠 index_dirty_ 标记   │
  └─────────────┴──────────────────────────────────────────────────────────────────────────────────────────┴───────────────────────────────────────────────────────┘

  依赖方向严格单向：VectorDb → HnswIndex → VectorTable，索引只通过 table_->vector(id) 读向量，从不拥有数据的副本。

  二、三条数据流

  写路径（三件事保持同步）：
  Add(v, meta)    table.Add: 归一化+追加 → id    → 索引存在且不脏 → index.Add(id)  增量插边
  Update(id,v,m)  table.Update: 就地覆盖+复活   → 索引存在 → index.Add(id)  幂等：先Remove再按新向量重插
  Delete(id)      table.Delete: 置tombstone     → 索引存在 → index.Remove(id)  剔除+邻居重连

  读路径：
  Search(q,k)          暴力：query 归一化 → 全扫 slot → 最小堆维护 top-K（跳过已删）
  SearchIndexed(q,k,ef) 若 index_dirty_ → 全量 Rebuild（仅 Load 后无有效索引时触发）
                        HNSW：从顶层贪心下探到第 0 层 → SearchLayer(ef 宽 beam) → 结果降序
  EnableIndex(m,efC)   建索引对象 + 全量 Rebuild

  持久化路径：Save = 表 + 索引一次落盘；Load = 向量段权威必读，索引段校验后才信，失败降级懒重建。

  三、文件格式 v3

  magic("MDBV") + version(3)
  + dim(u64) + metric(u8) + slot_count(u64)          ← 头部
  + 向量段：count×dim 个 float                        ← 权威数据
  + tombstone 段：slot_count 个 u8                    ← v2+
  + 元数据段：slot_count 个 [u64 len + 字节]           ← 权威数据
  + has_index(u8) + 索引段                            ← v3+
    索引段 = m(u64) efC(u64) enter_point(i32) top_level(i32) slot_count(u64)
            + 每个槽: level(i32) + 每层 [邻居数(u64) + nbr(u32)×N]

  读取校验逐层：版本 ∈ {1,2,3}；v1 无 tombstone 段全存活；v3 索引段校验 slot_count 匹配、level 合法、度数 ≤ 2M、入口与层高一致、图中节点数 == 存活向量数——任一不过 →
  弃索引段、懒重建，向量数据永不因索引损坏而丢失。

  四、关键设计决策及理由

  ┌──────────────────────────┬─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
  │           决策           │                                                   为什么                                                    │
  ├──────────────────────────┼─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ 软删除而非物理压缩       │ id 稳定不失效，代价是 slot 永不回收（slot_count 单调增）；换 Delete/Update 的 O(1)                          │
  ├──────────────────────────┼─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ 插入时归一化             │ 余弦 = 单位向量点积；范数只在写时算一次，查询免重复归一化                                                   │
  ├──────────────────────────┼─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ 索引引用表不复制         │ 单一事实来源、省一半内存；代价是索引与表必须同步维护                                                        │
  ├──────────────────────────┼─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ 增量维护 + 死边容忍      │ 删除走 O(M²) 节点级（重连保连通+修剪防度膨胀）；重连/修剪会打破边对称产生死边，但搜索跳过已删邻居，死边无害 │
  ├──────────────────────────┼─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ 向量段权威 + 索引段缓存  │ 索引是可再生的加速结构，损坏降级即自我修复，主数据永不丢                                                    │
  ├──────────────────────────┼─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ 堆缓存 score             │ 堆内存 {id,score} 而非裸 id，避免每次堆比较重算 64 维点积（构建 26s→10s，查询 2.4x）                        │
  ├──────────────────────────┼─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ AVX2 显式内联 + 标量回退 │ x86_64 走 _mm256 8 路并行，其余平台自动回退，无平台硬绑定                                                   │
  └──────────────────────────┴─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

  五、边界与取舍（诚实版）

  1. 单线程无锁——写路径多步非原子，并发读写不保证一致。服务并发查询前必须加锁。
  2. 纯内存——数据+索引全驻留；1M×384 维约 1.5GB+ 内存，规模化需 mmap。
  3. Save 非原子——写一半崩溃会留坏文件，无 WAL/日志回放。
  4. 索引段非必写——未启用索引时 Save 不写索引段，Load 后首次 SearchIndexed 才建。
